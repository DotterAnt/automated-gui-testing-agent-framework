# GUI authoring

Read this guide, template and supplied CSV once through `agta_help` topic `authoring` with `testCaseCsv`, or together through the shell when MCP is unavailable. Do not also read READMEs, the full contract, runtime modules, historical examples or workspace inventories. Ask targeted CLI/runtime help for missing signatures; signatures are compact by default, `detail: "full"` explains unresolved behavior.

## Develop the actual replay while exploring

1. `agta_explore Begin` with a unique absolute `runRoot`, supplied `testCaseCsv` and optional `potatoCliPath`. MCP defaults to `workflowMode: "Live"`; keep that configuration/evidence directory and follow its structured nextCall.
2. Save the template with one literal `StepBodies` scriptblock per CSV row. Implement the next row; leave later bodies empty while developing. Setup holds paths, shared state and helpers; GUI actions belong inside bodies.
3. `agta_replay Start` with `runRoot` and absolute `scriptPath` loads setup once without GUI actions. Equivalently use `agta_explore` with `action: "Replay", replayAction: "Start"`; subsequent Replay calls set replayAction to Step/Status/Repair/Close/Verify. Both transports reach the same session, even if the separate tool name is not advertised. `Step` executes the next body. Shared state, scope, ownership and paths survive. This tested code is the replay; do not translate a separate walkthrough into guessed code afterward.
4. Use bounded `agta_explore Batch` for read-only discovery between steps. Inspect receipts/images, develop the next body and call `Step`. Each row returns real `verificationCommandIds`. Review whether they prove the entire CSV expectation, then `agta_explore RecordSteps` with `{stepIndex,route,observedResult,verificationCommandIds}`. Dispatch alone cannot verify a row.
5. On failure, use `agta_replay Status`. The application remains at the failure. Inspect the retained evidence and structured command details; edit the saved failed body and restore its entry state with `Repair` requests `{command,arguments:[]}`. Retry `Step`. If the row was completed manually, `Skip` with a reason permits diagnostic continuation; it does not invent a pass. Do not run the whole script for each correction. Do not blindly repeat uncertain input.
6. `Close` cleans owned windows. An unchanged first-attempt success for every row, with reviewed recording and successful cleanup, qualifies directly; no second run is required. Repaired/skipped sessions preserve first-attempt successes separately. Finish/record missing exploration rows, then `Verify` executes the final revision from the beginning. Failed Verify keeps its live session at the failed body: Status/Repair/Step, continue, Close, then one clean Verify. Another full Verify is blocked while that session is open. Inspect `ok`, `qualifying`, failedSteps, assertions and cleanup. Live-mode standalone replay is allowed only for the final qualified script hash. Never weaken the CSV or deliver preflight as a passed test.

Step reloads only bodies; tested waits/selectors/assertions stay in the delivered code. Changes to setup require Close/Start because restarting setup could lose variables and window ownership. Detailed session rules: `docs/LIVE_REPLAY.md`, only when needed. `agta_inspect` returns the last few structured exploration/replay commands with filters. Use it instead of raw JSONL dumps. Full evidence remains on disk.

Without MCP, use recorded shell Batch exploration, RecordSteps, cleanup, Complete, the compact replay reference and template. A separate MCP walkthrough requires explicit Begin `workflowMode: "RecordedBatch"`; do not choose it merely because agta_replay is not separately advertised, since agta_explore Replay provides it. Preserve tested arguments/fresh identity resolution. Do not load full discovery history. Invoke shell entrypoints directly, without nested powershell.exe or OutputEncoding boilerplate:

~~~powershell
$requests = @'
[{"stepIndex":1,"command":"observe","arguments":["-Depth","3","-MaxElements","60"]}]
'@
& .\Invoke-Exploration.ps1 -Action Batch -RunRoot '<root>' -RequestsJson $requests
~~~

Auto retains a hidden execution worker. Use the native UTF-8 stdin fallback only if direct script invocation is unavailable; see `docs/MCP.md` for transport setup. Desktop calls are sequential; batch up to 20 known actions with a postcondition, stopping at unknown transitions/failures. Inspect Status before recovery.

## Controls, identity and evidence

- `GuiNavigation` is default. Application Open/Save/Print/edit actions use observed visible controls, including explicit CSV menu routes. No application hotkeys, clipboard, COM, direct document launches or synthetic expected outputs. Bounded navigation/focused input needs command reason/evidence. Preserve explicit `VisibleControls`. Shortcuts require explicit user/testcase authorization and operator-enabled capability; an agent reason or selector failure cannot authorize them.
- Start the executable with new-window ownership. Existing hosts are allowed; shared processes must not be killed. Reuse through the GUI/focus. Before a GUI handoff, `windows -Checkpoint`, then `focus -SinceCheckpoint` on its observed new window. Cleanup closes only registered processes/windows. Resolve handles, PIDs, bounds and guards again in each execution.
- Owned dialogs prefer `Scope FocusedWindow`. Broker dialogs: `windows -Foreground -WindowTitle '<observed title>' -TimeoutMs 15000`, assert count, then pass the complete fresh `data.foregroundSelector` as `WindowSelectorJson` with fallback reason/evidence. Bare `windows -Foreground` is an immediate snapshot, not a transition wait. Never assume the main app's PID or an appended extension. Structured *Json objects are accepted.
- Bound discovery. For current focus/filename use scoped `observe -Depth 0 -MaxElements 1`; focusedElement is reported even outside elements. Use observed IDs/classes as such, not Names. Name uses wildcards unless Regex is explicit. Resolve ambiguity from candidates; incomplete/depth-bounded searches do not prove absence. Probe optional first-run controls without input. Use tested minimal selectors and click Auto; never add guessed constraints during generation.
- Type full literal paths built from `Context.ExecutionEvidenceRoot`, with `PathKind SaveFile/OpenFile`, PreDelete and verified readback when supported. The directory exists; create only required extra directories. The GUI creates expected outputs. Omit InputDelayMs initially; preserve tested pacing. Focused input requires an observed editing target. After one failure inspect actual focus/readback; never assume lost text is path normalization. Commit-on-exit controls need a tested commit and separate content assertion.
- Inspect original screenshots inline; use their physical region origin for coordinates. Resolve current bounds and observed relative geometry, not frozen exploration points. Guarded ForegroundWindow captures that window. An opaque asynchronous action needs a tested readiness postcondition: expected-image wait for known content, or change/settle followed by actual content verification. A loading screen can be stable. Never repeat clicks or relax image tolerances to manufacture a pass.
- Every row needs real expected-result assertions. Use Assert-PotatoFound for presence, Assert-ExpectedResult for measured state, Assert-TextContains for content, wait-file with MinBytes/StableMs and Assert-FileWait for GUI outputs. Use fresh execution paths; AllowExisting is only for existing inputs. Reopen through the specified GUI route and check persisted content. For images/PDFs verify contents, orientation/cropping and unchanged originals where required. PDF text extraction can fail on an image-only PDF: inspect/render its actual pixels, never replace content verification with header/EOF/page-count checks. A screenshot's existence does not verify its contents. Dimensions/signatures/titles alone are insufficient. Diagnose failures without weakening assertions or omitting a specified Open with/menu route.
