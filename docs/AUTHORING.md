# GUI authoring

Read this guide, template and supplied CSV once through `agta_help` topic `authoring` with `testCaseCsv`, or together through the shell when MCP is unavailable. Do not also read READMEs, the full contract, runtime modules, historical examples or workspace inventories. Ask targeted CLI/runtime help for missing signatures; signatures are compact by default, `detail: "full"` explains unresolved behavior.

## Explore first, then verify the replay

1. `agta_explore Begin` with a unique absolute `runRoot`, supplied `testCaseCsv` and optional `potatoCliPath`. Start the owned application and inspect it with a small `Batch` now. No saved script or helper scaffolding is needed before the first GUI action. Resolve only launch/input facts required at this point.
2. Explore each CSV row through `Batch` requests `{stepIndex,command,arguments:[]}`. Use observed controls and bounded postconditions; stop at unknown transitions. After failure inspect `Status`/GUI, then continue from the current state. Review receipts/images against the CSV expectation and immediately `RecordSteps` with `{stepIndex,route,observedResult,verificationCommandIds}`. Dispatch alone does not prove success. Preserve tested arguments/waits and each row's receipt IDs.
3. Clean owned windows and `Complete`. Its compact replay reference is returned inline. After compaction restore only the needed row with `agta_help` topic `replay`, `runRoot` and `stepIndex`. Generate the template with one `StepBodies` scriptblock per CSV row using tested arguments, waits and fresh execution identities. Setup holds paths/shared state/functions; GUI actions belong in bodies or helpers called by bodies.
4. Run the complete saved script through the shell. It validates internally, executes rows in order, stops dependent rows after failure and cleans owned windows. Use the supplied CLI/CSV, completed runRoot and FrameworkRoot. For a script containing `exit`, launch it with `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <absolute script> -PotatoCliPath <cli> -TestCaseCsv <csv> -RunRoot <root> -FrameworkRoot <framework>`. This is one full execution, not a shell wrapper for each GUI action. If the shell tool yields a process/session ID, wait on that same process; do not launch another copy.
5. Inspect `ok`, row failures, assertions and cleanup. A successful full run completes validation immediately; do not run it twice. On failure use `agta_inspect` for bounded command history, fix the saved script and rerun it in full. Static preflight alone is not a completed GUI test. Full results and each replay attempt remain on disk.

Receipt assertions accept direct Result arguments or pipelines: `Invoke-StepCommand $Commands wait-element <tested arguments> | Assert-PotatoFound`. Assert-PotatoOk checks dispatch/verification success; Assert-PotatoFound needs existence/count/element evidence and cannot validate an observe receipt. Assertions must match the supplied CSV, without adding extra expectations. For PDF creation with an existence-only expected result, `wait-file` and `Assert-FileWait` are sufficient. Do not extract PDF text, render pages or compare image pixels for that row.

Without MCP, use recorded shell Batch exploration, RecordSteps, cleanup, Complete, the compact replay reference and template. Preserve tested arguments/fresh identities. Do not load full discovery history. Invoke shell entrypoints directly, without nested powershell.exe or OutputEncoding boilerplate:

~~~powershell
$requests = @'
[{"stepIndex":1,"command":"observe","arguments":["-Depth","3","-MaxElements","60"]}]
'@
& .\Invoke-Exploration.ps1 -Action Batch -RunRoot '<root>' -RequestsJson $requests
~~~

Auto retains a hidden execution worker. Use the native UTF-8 stdin fallback only if direct script invocation is unavailable; see `docs/MCP.md` for transport setup. Desktop calls are sequential; batch up to 20 known actions with a postcondition, stopping at unknown transitions/failures. Inspect Status before recovery.

Compact observe uses `elementColumns` once and `elementRows` arrays in those column positions. Bounds are physical `[x,y,width,height]`; flags list focused/disabled/offscreen/ambiguous when applicable. All nodes, selectors and patterns remain present; full objects stay in the transcript. Start with Depth 3/MaxElements 60 and target the relevant subtree before broadening. Repeated full-window trees and loading runtime modules consume context; screenshots do not replace selectors or content assertions.

## Controls, identity and evidence

- `GuiNavigation` is default. Application Open/Save/Print/edit actions use observed visible controls, including explicit CSV menu routes. No application hotkeys, clipboard, COM, direct document launches or synthetic expected outputs. Bounded navigation/focused input needs command reason/evidence. Preserve explicit `VisibleControls`. Shortcuts require explicit user/testcase authorization and operator-enabled capability; an agent reason or selector failure cannot authorize them.
- Start the executable with new-window ownership. Existing hosts are allowed; shared processes must not be killed. Before a GUI handoff, `windows -Checkpoint`, then `focus -SinceCheckpoint` using **data.checkpointId**, not explorationCommandId. In one Batch, give the windows request `key:"baseline"` and pass `{"resultRef":"baseline","path":"data.checkpointId"}` as the SinceCheckpoint value after the opening action. The same binding supports fresh WindowSelectorJson/WindowIdentityJson, ProcessId/NativeWindowHandle and screenshot references. Keys refer only to earlier commands in that batch; actual resolved arguments are recorded. Resolve identities again in replay; cleanup closes only registered windows/processes.
- Owned dialogs prefer `Scope FocusedWindow`. Broker dialogs: `windows -Foreground -WindowTitle '<observed title>' -TimeoutMs 15000`, assert count, then pass the complete fresh `data.foregroundSelector` as `WindowSelectorJson` with fallback reason/evidence. Bare `windows -Foreground` is an immediate snapshot, not a transition wait. Never assume the main app's PID or an appended extension. Structured *Json objects are accepted.
- Bound discovery. For current focus/filename use scoped `observe -Depth 0 -MaxElements 1`; focusedElement is reported even outside elements. Use observed IDs/classes as such, not Names. Name uses wildcards unless Regex is explicit. Resolve ambiguity from candidates; incomplete/depth-bounded searches do not prove absence. Probe optional first-run controls without input. Use tested minimal selectors and click Auto; never add guessed constraints during generation.
- Type full literal paths built from `Context.ExecutionEvidenceRoot`, with `PathKind SaveFile/OpenFile`, PreDelete and verified readback when supported. The directory exists; create only required extra directories. The GUI creates expected outputs. Omit InputDelayMs initially; replacement fields use stable readback and other editors use conservative pacing. Preserve tested pacing; do not select zero-delay bursts to fix partial input. Focused input requires an observed editing target. After one failure inspect actual focus/readback; never assume lost text is path normalization. Commit-on-exit controls need a tested commit and separate content assertion.
- Tool request strings are literal: `"$selector"` does not read a script variable. Pass actual JSON or an explicit batch resultRef. For example, key an awaited `windows -Foreground -WindowTitle '<observed dialog>' -TimeoutMs 15000` request `dialog`, then bind WindowSelectorJson to `{"resultRef":"dialog","path":"data.foregroundSelector"}`; supply fallback reason/evidence too. Variables inside saved PowerShell bodies resolve normally.
- Inspect original screenshots inline; use physical region origin/current bounds for coordinates. A capture without a wait is immediate and may precede rendering. After a transition, wait for an observed **destination** control, not a control on the screen just left. For an unknown opaque destination, take a small observe and screenshot; if loading, await screenshot WaitForChangeFrom on its content region, then inspect the returned pixels/controls before choosing input. Change/stability can still be loading. For known image content use WaitForImageMatch. Preserve tested waits; never repeat clicks or relax tolerances to manufacture success. A timeout on a guessed/source control does not establish an app defect or authorize an alternate CSV route.
- Every row needs real assertions. Use Assert-PotatoFound for presence, Assert-ExpectedResult for measured state, Assert-TextContains for content, wait-file with MinBytes/StableMs and Assert-FileWait for GUI outputs. Use fresh execution paths; AllowExisting is for inputs. Reopen and verify persisted content only when required by the CSV. For required image-content expectations use Assert-ImageRegionMatches against the input with expected ReferenceRotation/observed region; it honors EXIF display orientation without writing files. Diagnose retained captures using agta_inspect source image with imagePath/referencePath, optional region/referenceRotation (or Measure-ImageRegionMatch through shell), without rerunning input. Raw Width/Height may remain unchanged after EXIF rotation. Verify originals by hash where required. PDF existence-only expectations require only a newly created file, verified with wait-file and Assert-FileWait; no content inspection or rendering. Preserve all specified routes/expectations.
