# Agent instructions

First load the guide/template/CSV once: use `agta_help` topic `authoring` with the supplied `testCaseCsv` when MCP tools are available; otherwise read `docs/AUTHORING.md`, the supplied CSV and `templates/GeneratedScript.Template.ps1` together through the shell. Do not repeat the context through both transports. Use targeted CLI/runtime help for missing signatures; do not load whole modules, the full contract, old examples or unrelated testcases speculatively.

When agta_explore/agta_help MCP tools are available, prefer them for exploration and targeted help: agta_help topic authoring with the supplied testCaseCsv returns the guide/template/CSV together. Begin once, reuse its runRoot, Batch known routes, RecordSteps, Status and Complete through agta_explore. Keep desktop calls sequential. After a failed batch, inspect Status/GUI before a recovery batch. These tools preserve the same checks/receipts and avoid a fresh shell/client per request. See docs/MCP.md for one-time setup. Use the direct shell route below when MCP is unavailable; request login=false/no-profile at the shell-tool level when supported.

Unless the user requests a narrower scope, finish every row's GUI exploration and actual verification, record its receipts, Complete, generate, then execute and repair until the delivered revision passes all rows, assertions and cleanup. Syntax/preflight or a saved script is not completion. Incomplete exploration means resume missing rows. Answer intervening status questions briefly and continue. Stop only on explicit instruction or a concrete external blocker after bounded recovery; identify unfinished rows and the needed intervention. Never fabricate evidence or weaken expectations.

In PowerShell shell tools, call `& .\Invoke-Exploration.ps1 -Action Batch -RunRoot <root> -RequestsJson <literal JSON string>` directly. Avoid OutputEncoding/native piping and nested powershell.exe: they add a cold client process even when Auto keeps the worker warm. Call Begin, RecordSteps, Status, Complete and targeted help directly too. Use the guide's UTF-8 native-pipe fallback only when necessary. Begin once and reuse RunRoot. Interactive stdin can instead use Invoke-ExplorationStream.ps1. Keep desktop actions sequential, batch known routes and end at an observation when the next state is unknown. Batches/streams stop at failure. Inspect unknown outcomes before retrying. Read final workflow and record verified rows promptly. JSON newlines use \r\n, not PowerShell backticks inside a literal here-string. Compare explorationTiming with tool duration before blaming slow GUI actions.

GuiNavigation is default throughout; preserve explicit VisibleControls. Open, Save, Print and other application actions must use observed menu/button routes. A visible command or advertised accelerator does not authorize its hotkey. Navigation and focused typing require observed reason/evidence and confirmed focus. Application hotkeys, Shortcut clearing, clipboard, object models, direct file/protocol launches, synthetic outputs and private input backends require explicit user/testcase authorization; agent reasoning cannot supply it. Default MCP does not expose AllowShortcuts. Never edit integrations/server startup to enable shortcuts without a user's instruction. Generated scripts must preserve safe policy defaults and leave PolicyReason empty; only an authorized caller supplies exceptions. Selector failure never authorizes a bypass.

Start defaults to RequireNewWindow: never claim an old window or kill a shared host for isolation. Plain focus switches existing test windows without ownership. Before GUI opening into another app, use windows -Checkpoint, then focus its observed unique window with SinceCheckpoint for window-only cleanup. Close only registered processes/windows and verify actual exit.

Reuse tested minimal selectors, click Auto, pacing and transition guards. Command names include click, type, press-key, close-window and read; query exact names in targeted help. Resolve AmbiguousTarget from candidates. Avoid repeated guessed-label waits, observations used as delays, untested selector constraints and unconditional recovery actions. WaitBlockedByDialog returns a confirmed blocker/foreground guard: inspect it before recovery. Depth boundaries/SearchIncomplete require scoped discovery, not absence claims. Inspect screenshots before coordinates; use physical pixels and region origin.

Owned dialogs prefer FocusedWindow. Broker dialogs use windows -Foreground with the tested title and TimeoutMs; assert count, then pass its exact foregroundSelector as WindowSelectorJson with fallback evidence. Never assume readiness or the main app's PID. Runtime *Json options accept objects as well as strings. Scoped input must not steal another window's focus.

Use selector typing for writable controls; focused typing for a visibly entered opaque editor. Inspect keyboardFocus/error.focus after one failure and make one targeted correction. Omit InputDelayMs initially: verified standard single-line Edit replacement uses actual per-scalar acknowledgement without blind sleeps; other editors default to 5 ms per scalar. Preserve tested explicit pacing. If typing creates a new keyboard target, enter editing state first. ExpectedFocusJson waits without refocusing. PreDelete requires supported selection unless actual text readback proves the field empty. Verify proves current readback; commit/save/reopen assertions are separate.

Use Begin's existing absolute explorationEvidenceRoot and Context.ExecutionEvidenceRoot directly for filenames unless the testcase requires a subfolder; avoid an extra shell mkdir for optional organization. Use Join-Path with backslash separators and PathKind SaveFile/OpenFile. The GUI creates expected files; failed drawing never authorizes generating a seed image. Verify every content/persistence expectation; focused labels, signatures and titles do not prove table contents/counts. Use an actual content read or inspect the necessary screenshot regions. Image-only PDFs need image/content verification. Assert-ImageContainsColors scans actual output pixels in compiled code and can check ExpectedFormat; colors alone do not prove shape/layout. Assert-ZipTextContains verifies actual raw ZIP text; Read-AGTAZipText returns {name,text} entries, not CLI results. Read-AGTAArtifactBytes reads an exact Count.

Generate with Invoke-AGTATestPlan and InProcess transport. Read Complete's replayReferencePath first; routesPath retains full discovery history. After generation use agta_validate when available for full read-only preflight against the existing runRoot; a parser-only check is insufficient. Keep assertions and tested readiness checks. Runtime preflights every replay; rerun after behavior fixes without duplicate preflight. Check summary.failedSteps and cleanupOk first. Compact stdout links full result/command evidence. Successful cleanup needs no duplicate recovery. Never relocate a default save with Move-Item/Copy-Item/Rename-Item or pre-delete existing user files to imitate a GUI save; use the observed GUI route and fresh execution paths.

Each verification ID must follow a successful GUI action in its own row. A before-action screenshot cannot verify that action; remove the early ID and use a later reviewed receipt. Rows can be recorded in any order after valid exploration; late recording does not require repeating performed GUI routes.

MCP screenshot batches include original PNG/JPEG pixels inline; inspect them directly, without a second view_image call. Compact windows retain identity/guards/bounds while full properties stay in the transcript. Keep the checkpoint taken before a GUI handoff; later snapshots do not invalidate it (last 16 retained). A plain focus cannot register cleanup ownership. Never pre-close all windows of an application to hide an ownership error. For observed double-click routes use click -ClickCount 2, not separate commands; preserve a CSV-required menu route.

Standard single-line Edit replacement with PreDelete and exact Verify acknowledges every scalar before continuing. TextConsumptionFailed returns actual bounded readback and stops the remaining text without retry. Missing characters are not evidence of path-length/extension normalization; inspect actual text before one correction. Generated assertions must use actual conditions, never literal $true. Dimensions/file size/header alone cannot prove rotation direction, complete image preservation, original byte equality, or printed content. Keep those checks in every replay; exploration-only inspection does not satisfy replay expectations.

Use commentary for meaningful findings/failures, without narrating every successful click or row recording. For argument errors, reproduce the conversion with read-only code before another full GUI replay; do not remove guard fields or change scope to hide serialization failures.

Fresh windows -Foreground guards include NativeWindowHandle; use that entire foregroundSelector with focus -WindowSelectorJson to distinguish same-title sibling windows. WindowSelectorJson selects without ownership; WindowIdentityJson needs the complete ownedWindow receipt. Resolve PIDs/handles/checkpoints again during replay. Probe optional first-run state before acting and preserve CSV-specific menu routes. For opaque asynchronous controls, await changed/settled content with screenshot -WaitForChangeFrom <before.png> -ChangeRegionJson <observed rectangle> -TimeoutMs 2000 -StableMs 150; keep identical capture bounds/origin, exclude hover/focus indicators, assert conditionMet and inspect the retained frame. Do not repeat a state-changing click from an immediate stale capture. Assert-ImageRegionMatches compares actual screenshot/render/output content with the complete reference. Screenshot existence or nonzero file size cannot verify contents. Render actual image-only PDF output and retain content/cropping checks in replay; raw PDF markers cannot replace them.
