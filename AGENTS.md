# Agent instructions

Read `docs/AUTHORING.md`, the testcase CSV, and `templates/GeneratedScript.Template.ps1` together first. Use the guide's `powershell.exe -NoProfile -ExecutionPolicy Bypass -File Invoke-Exploration.ps1` entrypoint with UTF-8 JSON piped to `-RequestsStdin` in ONE shell tool call per batch. Do not create a separate JSON file with a file-edit tool for every batch; RequestsPath remains available for existing files. Begin once; subsequent Batch/RecordSteps/Status/Complete calls need only that exact RunRoot. Do not construct temporary wrapper scripts or pass array arguments across `powershell.exe -File`. Read multiple needed CLI topics in one `help -Topics click,type,observe` call, or runtime signatures in one `Get-RuntimeHelp.ps1 -Names Invoke-StepCommand,Assert-TextContains` call. Read full source only for a concrete unresolved defect.

The default interaction policy is GuiNavigation for exploration, execution, and cleanup. Use visible GUI routes. Bounded `press-key` navigation (Tab/ShiftTab/Enter/Escape/arrows) and `type -TargetMode Focused` for an observed opaque editor require fallback reason/evidence and confirmed application focus. Preserve an explicitly requested VisibleControls policy, which forbids navigation keys. Application hotkeys, Shortcut clearing, clipboard, object models, file-association opening, and creating expected outputs directly remain forbidden without explicit authorization where applicable. A selector failure is not authorization to bypass the GUI.

Plan, then perform the COMPLETE testcase through the GUI, including save, close/reopen, print/export, required assertions, and cleanup, before writing the final script. Use `Invoke-Exploration.ps1` to record commands by CSV row and verified routes in `logs/exploration.json`; every row needs a real observation receipt. The API workflow exposes the same checkpoint through `run_potato` and `record_exploration_step`. Incomplete exploration blocks development and execution. Do not invent receipts, output artifacts, or PASS assertions to satisfy the gate. If blocked, report the missing route honestly.

Keep desktop commands sequential. Reuse selectors, read only targeted help, and discover only unknown controls within that full walkthrough. Generated execution uses InProcess transport. `potato-stream.ps1` supports clean persistent pipes and stops on the first failure by default; do not queue dependent actions across an unknown state. After start, inspect the actual UI. Prefer element selectors and relative clicks to fixed screen coordinates. Commit an edit through a visible control or permitted Enter before asserting its saved value; `type -Verify` only checks current readback and never commits or retypes. Use recorded CLI input instead of compiling local SendKeys/SendInput helpers. No application-specific selectors or expected content belong in framework/CLI helpers.

For custom canvases, focused typing needs the observed GUI editing state, not a writable UIA selector. The CLI corroborates native keyboard focus even when UIA's focus flag disagrees. Use observe.keyboardFocus and error.focus; after one focused-input failure make one targeted correction, not repeated guessed focus probes/source reads. Preserve observed ExpectedFocusJson guards when generating. Semantic clicks preserve popup focus by default. read-pdf handles transient locks internally; close-window returns requests and still requires exit verification.

Use compact observations and Scope FocusedWindow for owned dialogs. Prefer minimal observed name/id selectors and click Auto; an opaque Pane role may change when its provider initializes. Avoid repeated timed probes of guessed labels. Reuse the successful commands in exploration-routes.json; do not add untested selector constraints during generation. Use the template's Invoke-AGTATestPlan for row sequencing, dependent skips and cleanup. Generated execution already preflights itself, so repairs need no separate repeated preflight process before rerunning.

See `docs/GENERATED_SCRIPT_CONTRACT.md` only for further result/schema details. Never weaken requirements to improve elapsed time.

All framework paths now default observe to Compact; preserve an explicit Format and tested pacing when generating. Default typing is paced Unicode (InputDelayMs 5); TypeByCharacter retains legacy 50 ms. Verify actual text, not character counts/line-column labels. A new process may restore documents; establish a blank GUI state before typing. For a system-hosted dialog, use guarded Scope ForegroundWindow with exact observed WindowSelectorJson Name/ClassName and fallback evidence; never adopt its host process for cleanup. Wait for enabled controls and the next dialog instead of blind repeated submit clicks or fixed sleeps. SearchIncomplete means narrow the observed scope.

Resolve AmbiguousTarget from returned candidates before clicking. For selected opaque inputs use ExpectedFocusJson to wait without clicking away the selection; prefer writable PreDelete plus Verify when available. Successful verified typing is an exploration receipt for current text, not proof of saving. For reopen expectations read actual content and assert every required fragment with Assert-TextContains; an element title alone is insufficient.

Use Begin's existing absolute explorationEvidenceRoot for exploration outputs and Context.ExecutionEvidenceRoot for generated execution. Add type -PathKind SaveFile/OpenFile for filename fields; missing parents or input files then fail before typing. Keep the full literal path and use that same path for file assertions. Preparing an empty infrastructure directory does not create the expected output; the GUI must create the file. Preserve tested transition guards instead of adding untested waits. Respect depthBoundaryReached: try scoped deeper discovery or a short visible label-fragment query before claiming UIA absence. Inspect screenshots before coordinate fallback; screenshots and clicks use physical pixels, not scaled preview coordinates. Read verification.eligible and use multiple verificationCommandIds for compound expectations. After a failed replay, read summary.failedSteps and cleanupOk before any recovery; successful cleanup needs no duplicate close/process checks, and the next replay runs its own preflight.
