# Agent instructions

Unless the user explicitly requests a narrower scope, creating a test script means finishing the entire workflow: perform every CSV row through the GUI, record and complete exploration, generate the script, then execute and repair it until the current revision passes every row, all required assertions, and cleanup. Continue through these stages without waiting for another user message. A partial walkthrough, saved artifact, written script, or successful syntax/preflight check is not completion. `Exploration is incomplete` means resume the existing walkthrough and finish/record the missing rows; it is not an acceptable final-delivery caveat. After any behavior change, replay the corrected script before claiming completion. Stop early only if the user requests it or a concrete blocker remains after bounded, permitted recovery and requires unavailable access, information, or capability; identify the unfinished rows, evidence, and intervention needed. Never invent coverage or weaken assertions to finish.

Read `docs/AUTHORING.md`, the testcase CSV, and `templates/GeneratedScript.Template.ps1` together first. Use the guide's `powershell.exe -NoProfile -ExecutionPolicy Bypass -File Invoke-Exploration.ps1` entrypoint with UTF-8 JSON piped to `-RequestsStdin` in ONE shell tool call per batch. Do not create a separate JSON file with a file-edit tool for every batch; RequestsPath remains available for existing files. Begin once; subsequent Batch/RecordSteps/Status/Complete calls need only that exact RunRoot. Do not construct temporary wrapper scripts or pass array arguments across `powershell.exe -File`. Read multiple needed CLI topics in one `help -Topics click,type,observe` call, or runtime signatures in one `Get-RuntimeHelp.ps1 -Names Invoke-StepCommand,Assert-TextContains` call. Read full source only for a concrete unresolved defect.

The default interaction policy is GuiNavigation for exploration, execution, and cleanup. Use visible GUI routes, including a file manager's address bar, file selection, double-click/Open/Open with and navigation into a viewer. Bounded `press-key` navigation (Tab/ShiftTab/Enter/Escape/arrows) and `type -TargetMode Focused` require fallback reason/evidence and confirmed focus. Preserve an explicitly requested VisibleControls policy. Application hotkeys, Shortcut clearing, clipboard, object models, non-GUI file/protocol launch wrappers and directly creating expected outputs remain forbidden without authorization. A selector failure is not authorization to bypass the GUI.

Framework start defaults to RequireNewWindow: existing shell/application processes are allowed, but an old window is never silently claimed. It tracks a new process when available, otherwise only the new window. Use windows -Checkpoint before a GUI action that opens another app; focus its observed unique window with -SinceCheckpoint <returned checkpointId> to register window-only cleanup. Plain focus switches the interaction target without claiming cleanup ownership. Reuse an already open test window through focus; do not relaunch merely to switch apps. Never keep a launcher alive or terminate a shared host to satisfy ownership. For external dialogs, windows -Foreground returns the actual title/class guard; use it instead of guessing.

Plan, then perform the COMPLETE testcase through the GUI, including save, close/reopen, print/export, required assertions, and cleanup, before writing the final script. Use `Invoke-Exploration.ps1` to record commands by CSV row and verified routes in `logs/exploration.json`; every row needs a real observation receipt. The API workflow exposes the same checkpoint through `run_potato` and `record_exploration_step`. Incomplete exploration blocks development and execution: use Status, finish and record the missing rows, then Complete and continue to generation and execution. Do not invent receipts, output artifacts, or PASS assertions to satisfy the gate.

Keep desktop commands sequential. Reuse selectors, read only targeted help, and discover only unknown controls within that full walkthrough. Generated execution uses InProcess transport. `potato-stream.ps1` supports clean persistent pipes and stops on the first failure by default; do not queue dependent actions across an unknown state. After start, inspect the actual UI. Prefer element selectors and relative clicks to fixed screen coordinates. Commit an edit through a visible control or permitted Enter before asserting its saved value; `type -Verify` only checks current readback and never commits or retypes. Use recorded CLI input instead of compiling local SendKeys/SendInput helpers. No application-specific selectors or expected content belong in framework/CLI helpers.

For custom canvases, focused typing needs the observed GUI editing state, not a writable UIA selector. The CLI corroborates native keyboard focus even when UIA's focus flag disagrees. Use observe.keyboardFocus and error.focus; after one focused-input failure make one targeted correction, not repeated guessed focus probes/source reads. Preserve observed ExpectedFocusJson guards when generating. Semantic clicks preserve popup focus by default. read-pdf handles transient locks internally; close-window returns requests and still requires exit verification.

Use compact observations and Scope FocusedWindow for owned dialogs. Prefer minimal observed name/id selectors and click Auto; an opaque Pane role may change when its provider initializes. Avoid repeated timed probes of guessed labels. Reuse the successful commands in exploration-routes.json; do not add untested selector constraints during generation. Use the template's Invoke-AGTATestPlan for row sequencing, dependent skips and cleanup. Generated execution already preflights itself, so repairs need no separate repeated preflight process before rerunning.

See `docs/GENERATED_SCRIPT_CONTRACT.md` only for further result/schema details. Never weaken requirements to improve elapsed time.

All framework paths default observe to Compact; preserve an explicit Format and tested pacing when generating. Default typing is paced Unicode (InputDelayMs 5); TypeByCharacter retains legacy 50 ms. Verify actual text. A new window/process may restore documents; establish the required initial GUI state. System-hosted dialogs allow guarded Scope ForegroundWindow observation, clicks, type and press-key with exact observed WindowSelectorJson and fallback evidence; focused typing also needs ExpectedFocusJson. This does not change the working window or claim cleanup ownership. Wait for enabled controls and the next dialog instead of blind repeated submit clicks or sleeps. SearchIncomplete means narrow the observed scope.

Resolve AmbiguousTarget before clicking. ExpectedFocusJson waits without clicking away a selection. PreDelete uses supported UIA/native text selection plus keyboard Backspace, including in Focused mode; arbitrary opaque canvases still need a visible selection route. PathKind enables exact readback by default, including standard Windows Edit fields with missing UIA patterns. Inspect a mismatch and reset the field before one tested slower retry; keep full absolute paths rather than falling back to the dialog's remembered directory. Verified typing proves current text, not saving. Reopen assertions must check actual content; a title or file signature is insufficient. Image-only PDFs need visual/content verification, not text extraction. Do not turn exploratory recovery actions (such as a second drag or switching the wrong mode) into unconditional replay steps.

Use Begin's existing absolute explorationEvidenceRoot for exploration outputs and Context.ExecutionEvidenceRoot for generated execution. Add type -PathKind SaveFile/OpenFile for filename fields; missing parents or input files then fail before typing. Keep the full literal path and use that same path for file assertions. Preparing an empty infrastructure directory does not create the expected output; the GUI must create the file. Preserve tested transition guards instead of adding untested waits. Respect depthBoundaryReached: try scoped deeper discovery or a short visible label-fragment query before claiming UIA absence. Inspect screenshots before coordinate fallback; screenshots and clicks use physical pixels, not scaled preview coordinates. Read verification.eligible and use multiple verificationCommandIds for compound expectations. After a failed replay, read summary.failedSteps and cleanupOk before any recovery; successful cleanup needs no duplicate close/process checks, and the next replay runs its own preflight.
